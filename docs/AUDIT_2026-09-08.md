## Seção A — Achados novos (fora de P1–P35)

### 🔴 A-01 — Contrato app↔backend quebrado: uma baseUrl, zero prefixo, `/auth` que não existe mais

**Local:**
- `lib/core/api/api_client.dart:8-11` — `const _baseUrl = String.fromEnvironment('API_URL', defaultValue: 'http://localhost:3001')`
- `lib/features/auth/data/datasources/auth_datasource.dart:42,66,87` — `POST /auth/register`, `POST /auth/login`, `GET /auth/status`
- `lib/features/auth/data/datasources/account_service.dart:59-122` — `/auth/forgot-password`, `/auth/reset-password`, `GET/PUT /auth/profile`
- `lib/features/patient/data/datasources/patient_remote_datasource.dart:23-27,62-100` — `/readings`, `/alerts`, `/carbs`, `/insulin`, `/settings/alerts` sem prefixo
- `backend/services/glucose-service/src/app.ts:55-61` — monta só `/readings|/carbs|/insulin|/alerts|/settings|/dashboard|/internal`; **não há `/auth`**
- `backend/services/gateway/src/app.ts:67-102` — tudo sob `/api/v1/*`; `backend/docker-compose.yml:79-80` publica **apenas** o gateway (`3000:3000`)

**Problema:** com `API_URL=:3001` (o default e o que o CLAUDE.md manda), todo `/auth/*` responde 404: login e registro falham com `AuthError.serverError` (o `rethrow` de `auth_datasource.dart:58,73` cai no mapeador genérico), e usuário com token salvo entra em modo "autenticado offline" **permanente** — `isLoggedIn()` classifica 404 como `unreachable` (`auth_datasource.dart:90-98`, só 401/403 invalidam), então `AuthCubit` emite `authenticated` otimista para sempre. Com `API_URL=:3000` (gateway, a única porta publicada no compose), **todas** as rotas 404am por falta do prefixo `/api/v1`. Não existe valor de `API_URL` que faça o app inteiro funcionar.

**Fix proposto:** apontar o app para o gateway e absorver o prefixo num único lugar:
1. `api_client.dart`: default `http://localhost:3000` e `BaseOptions(baseUrl: '$_baseUrl/api/v1')` — nenhum datasource muda de caminho (o gateway proxeia `/api/v1/auth/*` → auth-service `/auth/*` e `/api/v1/{readings,carbs,insulin,alerts,settings}` → glucose-service, então os paths relativos atuais continuam válidos).
2. Decidir perfil: manter `GET/PUT /auth/profile` (proxied, responde só a metade conta) **ou** migrar `AccountService` para `GET/PUT /api/v1/me` (composição completa conta+paciente — recupera as duas "regressões conhecidas" do README). Recomendado: `/me`. Ver decisão H-1.
3. Atualizar o exemplo `--dart-define` no CLAUDE.md e `docs/guides/setup-and-build.md` no mesmo PR.

**Aceite:** com `docker compose up --build` em `backend/`, o app com `API_URL=http://<ip>:3000` completa registro → login → escrita de carb → push do sync (linha no Postgres) → edição de perfil → logout → login.
**Verificação:** `flutter test --no-pub` (ajustar fakes de path se necessário) + roteiro manual acima; `curl -s localhost:3000/api/v1/auth/login -X POST -H 'content-type: application/json' -d '{...}'` responde 200/401, nunca 404.
